# Tesla Navi

현재 버전 **0.5.33**. 안내 설정에서 Gemini 목소리 30종과 말하기 속도(0.8~1.5배, 기본 1.25배)를 선택합니다. API 키는 앱에 암호화 저장합니다. 카메라 안내는 미리 합성해 재사용하며, 주행 중 응답이 2.5초를 넘으면 휴대폰 기본 음성으로 안내합니다. 설치된 이전 음성 모델은 업데이트 후 자동으로 정리합니다. 차량 등록 키와 기존 설정은 유지합니다. [Gemini 설정](GEMINI.md).

2021~2022년식 Tesla Model 3 / Model Y용 개인 Android 앱.

현재 버전 **0.5.33**은 차량 접근 시 자동 연결, 메인 화면의 배터리·주행 가능 거리 표시, 주행 시작 후 카카오내비 단속카메라 화면·음성 안내, 설정에서 켜는 통계 탭(충전·주행 기록), 안내 설정에서 고르는 Gemini AI 안내 음성을 포함합니다. 고속도로 500 m·일반도로 300 m에서 카메라 존재를 알리고, 접근 구간에서 단속지점 제한속도보다 5 km/h 이상 빠르면 과속을 경고합니다. 제공된 APK에는 사용자가 지정한 네이티브 앱 키가 기본으로 포함됩니다. 실차 연결, 접근 감지, 카카오 서버 인증 및 실제 주행 안내는 사용자 차량에서 확인해야 합니다.

0.5.32 Gemini 음성: 안내 설정에 API 키 등록·변경·삭제와 Gemini AI 음성 선택을 추가했습니다. 키는 휴대폰에 암호화해 저장하며, 반복 안내는 음성 파일을 재사용합니다. 네트워크 실패·응답 지연·사용 한도 초과 때는 기본 음성으로 안내합니다. 무료 키 발급과 사용법은 [GEMINI.md](GEMINI.md)에 있습니다.

0.5.17 하차 추정 보강: P단이 확인되면 안내 유지 대상에서 제외하고, Bluetooth 연결 해제나 GPS 저속 이동만으로는 하차로 판단하지 않습니다. 안내 설정의 **연결 끊김 후 하차 감지 → 신체 활동 권한 허용**은 선택 사항입니다. 허용한 경우 차량 연결이 끊긴 뒤 안내를 유지하는 동안만 휴대폰의 `TYPE_STEP_DETECTOR`를 구독합니다. 원본 GPS가 15초 넘게 비지 않고 1~8 km/h 이동을 2분 이상 보이며 50 m 이상 이동하고, 그 구간에서 40걸음 이상·60초 이상에 걸친 보행·최근 10초 안의 걸음까지 함께 확인되면 하차로 추정해 안내와 재연결 서비스를 종료합니다. 속도가 올라가거나 위치가 불확실하면 보행 판정을 새로 시작합니다. 판정은 추정이며 확정적인 하차 신호가 아닙니다. 권한 거부·센서 미지원·보행 근거 부족이면 기존 안내 유지와 10분 정지 종료를 그대로 적용합니다. 센서는 안내 유지가 끝나면 해제하고 걸음 기록은 저장하지 않습니다. 안내 유지·차량 재연결·종료 사유는 좌표 없이 연결 기록에 남깁니다.

0.5.16 연결 끊김 후 안내 유지: 주행 중 차량 연결이 비정상적으로 끊기면 마지막으로 확인한 목적지 좌표와 기존 카카오 경로를 유지하고, 휴대폰 GPS의 위치·속도로 카메라 안내와 과속 경고를 계속합니다. 차량 재연결도 계속 시도하며, 재연결되면 최신 차량 정보로 복귀합니다. 연결이 끊긴 뒤 마지막 이동 확인부터 10분 동안 이동이 확인되지 않으면 안내와 해당 연결 서비스를 종료합니다. 이동은 신선한 GPS 속도 3 km/h 이상 또는 원본 GPS 좌표의 30 m 이상 변위로 판단하며, 같은 GPS 표본의 재전달·오래된 표본·작은 위치 흔들림은 정지 타이머를 연장하지 않습니다. GPS를 못 받으면 경고를 멈추고 같은 10분 제한을 적용합니다. 목적지 좌표가 없거나 주차 상태에서 끊기면 이 기능을 시작하지 않고, 사용자가 연결 종료를 누르면 즉시 종료합니다. 목적지는 실행 중인 서비스의 메모리에만 유지하므로 앱 강제 종료 후 이전 경로로 자동 안내하지 않습니다. 가상 시간으로 연결 복구와 안내 서비스의 수명을 함께 검증했으며, 실차 확인은 별도입니다.

0.5.8 잠든 차량 대기: 차를 세워 두고 휴대폰이 근처에 있으면 자동 연결이 1분 남짓마다 차량 인증을 시도하다 4초 시간 초과로 실패하기를 반복했습니다. 주차 중 인포테인먼트가 잠들어 인증에 답하지 못하기 때문입니다. 이제 인증 전에 VCSEC에 인증 없이 차량 상태를 묻고, 잠들어 있으면 인증을 건너뛰고 "차량 잠듦 · 깨어나면 연결합니다"로 기다립니다. 한 번의 시도가 약 35초에서 짧은 연결 한 번으로 줄어 배터리 사용이 줄어듭니다. 자동 연결의 인증 시간 초과 재연결은 3회에서 1회로 줄였고, 같은 결과가 반복되는 자동 연결 시도는 연결 기록에 횟수만 남겨 기록이 금방 밀려나지 않게 했습니다. 잠든 실제 차량의 응답은 아직 확인하지 않았습니다.

0.5.6 위치 진단: 차량 주행 정보를 조회할 때 차량 위치도 함께 요청하고, 차량이 위치를 주는지를 **연결 기록**에만 남깁니다. 화면은 바뀌지 않습니다. 연결마다 처음 한 번과 상태가 바뀔 때 위치 제공 확인·위치 상태 없음·좌표 없음·거부(사유) 중 하나를 남기고, 위치를 받는 동안에는 5분마다 조회·좌표·GPS 시각 갱신 횟수와 대략적인 이동 거리를 요약합니다. 좌표 자체는 기록하지 않습니다. 차량이 위치 요청을 거부하면 그 연결에서는 주행 정보만 다시 조회하므로 목적지·카메라 안내는 그대로입니다. 주행 기록 기능의 위치 출처를 정하기 위한 확인이며, 설계는 [TRIP_LOG.md](TRIP_LOG.md)에 있습니다. 실차 결과는 아직 확인하지 않았습니다.

0.5.5 접근 감지: 차량 광고 검색을 앱 프로세스 대신 Android 시스템이 맡도록 PendingIntent 방식으로 바꿨습니다. 필터는 기존과 같이 인증한 등록 차량의 VIN으로 계산한 광고명이고 저전력 모드입니다. 시스템이 앱 프로세스를 정리해도 검색 등록이 남아 있다가, 차량 신호를 받으면 앱을 깨워 대기 서비스를 복원합니다. 대기 알림과 연결 판단(RSSI·60초 재시도·출발 대기)은 그대로입니다. Android 12 이상에서는 백그라운드에서 대기 서비스 복원이 거부될 수 있으며, 이때는 앱을 다시 열어야 합니다. 프로세스 정리 후 복원과 절전 중 수신은 실차 검증이 필요합니다.

0.5.4 통계 탭: 차계부 탭을 **통계** 탭으로 바꾸고 화면 위쪽에 `충전`·`주행` 세그먼트를 두었습니다. 설정 스위치 이름은 **통계 탭**이며 저장 키는 그대로라 켜 둔 상태가 유지됩니다. 탭 아이콘은 막대 차트, 세그먼트 아이콘은 EV 충전소와 경로이고, 모두 Material 아이콘(Apache-2.0) 경로를 그대로 옮겨 확장 아이콘 라이브러리 없이 씁니다. 세그먼트 위에는 고른 차량의 이번 달 주행거리와 충전량·충전비를 한 줄로 보여 줍니다. 주행 기록은 카메라 안내와 같은 기준으로 P단을 벗어나 3 km/h 이상이면 시작하고 P단에서 끝냅니다. BLE가 잠깐 끊겨도 이어지며 표본이 10분 넘게 끊겨야 나눕니다. 0.3 km 미만 이동은 남기지 않습니다. 거리는 누적 주행거리 차이로, 차량이 주행거리를 보내지 않으면 속도 적분으로 계산합니다. P단에 두는 순간 충전 상태를 바로 읽어 3분 안에 받은 배터리 값을 종료 배터리로 씁니다. 주행 기록은 월별로 묶어 횟수·거리·시간 합계를 보여 주고, 각 카드는 거리 배지(정수 km, 1 km 미만은 100 m 단위), 시작→종료 시각, 운전 시간·평균 속도·배터리 변화 칸으로 나눴습니다. 두 기록 사이에 누적 주행거리가 1 km 이상 비면 "기록되지 않은 주행"으로 표시합니다. 충전 기록 카드는 직접/자동 태그를 없애고, ⋮ 메뉴에 **충전단가 수정**을 추가했습니다. 충전마다 단가를 따로 정하면 그 충전의 km당 충전비와 평균·월 충전비를 그 단가로 다시 계산하고, 따로 정하지 않은 충전은 기본 충전 단가를 따릅니다. 카드 항목은 제목과 값을 가운데로 맞췄습니다. 진행 중이던 주행은 앱 프로세스가 강제 종료되면 남지 않고, 휴대폰이 연결된 동안만 기록됩니다. 실차 주행 기록은 아직 확인하지 못했습니다.

0.5.2 차계부: 오른쪽 위 설정 버튼(하단 설정 탭을 켰다면 설정 탭)에서 **차계부 탭**을 켜면 하단 탭 바에 차계부 탭이 생깁니다. 하단 설정 탭이 꺼져 있으면 탭 바는 메인·차계부, 켜져 있으면 메인·차계부·설정입니다. 차계부를 끄면 탭이 사라지고 이전 화면 그대로 보입니다. 충전 기록마다 이전 충전 이후 주행거리를 이번 충전량으로 나눠 전비(km/kWh)를 내고, 충전 단가를 곱해 km당 충전비(원/km)를 보여줍니다. 기록이 셋 이상이면 전체 평균도 표시합니다. 단가 기본값은 환경부 공공 완속(30 kW 미만) 요금 295원/kWh(2026년 8월 개편)이며 차계부 탭의 **단가 변경**에서 바꿀 수 있습니다. 차계부는 배터리 표시가 쓰는 충전 상태 조회(연결 직후 한 번, 이후 5분마다)를 같이 써서 요청을 늘리지 않고, 충전 케이블이 꽂혀 있는 동안만 1분 간격으로 다시 읽습니다. 케이블이 분리된 상태에서 새 충전이 확인되면 그 시점의 주행거리와 충전량을 자동으로 기록합니다. 차량별 첫 조회는 기준값으로만 저장하므로 자동 기록은 그다음 충전부터 쌓입니다. 자동 기록 충전량은 차량이 보고한 배터리 입력량이라 충전기 과금량보다 작게 나올 수 있습니다. 차계부는 차량마다 따로 관리합니다. 차량이 여러 대면 차계부 탭 위쪽에서 차량을 고르고, 이 선택은 연결할 차량 선택을 바꾸지 않습니다. 충전 기록은 월별로 묶어 횟수·충전량·대략의 충전비를 보여주고, 각 기록은 전비 배지, km당 충전비, 주행·충전량·누적 주행거리 칸으로 나눠 표시합니다. 기록 설명은 `충전 기록` 옆 안내 아이콘을 누르면 다이얼로그로 열립니다. 기록 직접 추가와 기록 메뉴의 삭제를 지원하며, 연결 중인 차량을 고른 상태라면 입력 창에 현재 주행거리를 미리 채웁니다. 충전 상태 조회가 실패해도 목적지 조회와 카메라 안내는 계속됩니다. 충전 상태 조회 자체는 0.5.1에서 실차로 확인했지만, 충전 중 여부·충전량(`charging_state`, `charge_energy_added`)과 주행거리(`odometer_in_hundredths_of_a_mile`) 필드는 아직 실차에서 확인하지 못했습니다.

0.5.1 배터리 표시: 메인 화면 제목 아래 카드에 차량 배터리 %와 주행 가능 거리(km)를 보여 줍니다. 하단 설정 탭을 끈 기본 화면과 설정 탭을 켰을 때의 메인 탭에 모두 나옵니다. 숫자는 차량 화면·Tesla 앱과 같은 `ChargeState`의 `battery_level`과 정격 주행 가능 거리 `battery_range`(마일을 km로 변환)이고, `usable_battery_level`·`est_battery_range`는 쓰지 않습니다. 연결 직후 첫 주행 상태를 읽고 나서 충전 상태를 한 번 요청하며, 그 뒤로는 5분마다 다시 읽습니다. 충전 상태 요청은 4초 안에 끝나도록 제한해 5초 주기의 목적지 조회를 늦추지 않습니다. 응답이 없거나 차량이 거절해도 연결과 목적지 조회는 그대로 이어지고, 3회 연속 받지 못하면 10분 간격으로만 다시 요청합니다. 마지막으로 받은 값은 차량별로 앱 전용 `shared_prefs/battery.xml`에 저장되므로 연결이 끊기거나 앱을 다시 열어도 "마지막 수신 12분 전"처럼 경과 시간과 함께 흰색으로 남고, 연결 중 10분 안에 받은 값은 민트색으로 바뀝니다. 2026-10-24 사용자 차량에 BLE 조회 전용 키(`ROLE_VEHICLE_MONITOR`)로 연결했을 때 첫 주행 상태 약 0.5초 뒤 충전 상태를 받아 배터리 62%·주행 가능 237 km를 표시하는 것을 확인했습니다. 차량 소프트웨어가 바뀌면 달라질 수 있어, 연결할 때마다 **연결 기록 보기**에 `충전 상태 수신 · 배터리 78% · 주행 가능 352 km`, `충전 상태 없음`, `충전 상태 조회 실패 · 사유` 가운데 하나를 남깁니다. 차량 화면 숫자와 같은지는 직접 비교해 주세요. 같은 결과가 반복될 때는 기록하지 않아 160개 한도를 채우지 않습니다. 주행 상태 조회의 오류 판정도 고쳤습니다. 오류 값(`OPERATIONSTATUS_ERROR`, 1)을 2로 잘못 비교하던 탓에 차량이 조회를 거절해도 사유가 보이지 않았고, 거절 응답에 주행 상태가 함께 오면 그대로 받아들였습니다. 이제 두 조회 모두 `차량 조회 실패: 사유`로 실패 처리하고 기존 재연결 흐름을 탑니다.

0.5.0 설정 탭 기능: 메인 화면 오른쪽 위에 설정 버튼을 추가했습니다. 기본 화면 구성은 0.4.6과 같습니다. 설정 버튼을 누르면 설정 팝업이 열리고, **하단 설정 탭**을 켜면 화면 아래에 아이콘만 있는 낮은 탭 바(메인·설정)가 생깁니다. 이때 차량 등록·선택, 차량 연결·앱 키 등록, 자동 연결, 안내 설정, 연결 기록은 설정 탭으로 옮겨지고 메인 탭에는 연결 상태, 단속카메라 안내, 차량 목적지만 남습니다. 설정 탭이 켜져 있는 동안 오른쪽 위 설정 버튼은 숨기며, 설정 탭의 같은 스위치를 끄면 0.4.6 화면과 설정 버튼으로 돌아갑니다. 설정 탭에서 뒤로 가기를 누르면 메인 탭으로 이동합니다. 스위치 상태는 앱 전용 `shared_prefs/features.xml`에 저장합니다.

0.4.6 설정 진입: 화면 상단 제목 아래에 민트색 전체 너비의 안내 설정 버튼과 조절 아이콘을 배치했습니다.

0.4.5 안내 복구: 카카오 초기화·안내 시작 실패 시 5~30초 간격으로 재시도하며 주차·연결 종료 시 재시도를 취소합니다. 접근 구간의 전체 카메라에서 과속 여부를 확인하고 경고 대상 카메라의 제한속도를 화면에도 표시합니다. TTS 초기화 실패와 경고음을 분리했습니다. 5분 주차 시 강제 연결 해제를 제거하여 재출발을 감지합니다. 대신 차량 근처에서 오래 대기하면 연결·배터리 사용이 늘 수 있습니다. 경고음은 부드러운 시작·끝과 배음이 있는 48 kHz 종소리로 변경했습니다. 음원 출처 후보와 구현 설명은 [AUDIO.md](AUDIO.md)에 있습니다.

0.4.4 소리 테스트: 안내 설정에서 카메라 음성과 과속 경고음을 각각 들어볼 수 있습니다. 실제 주행과 같은 음성·경고음 출력을 사용하며 차량 연결이 필요하지 않습니다. 설정한 앱 음량이 적용되고, 경고음은 약 6초 뒤 종료합니다. 테스트 중지·설정창 닫기·앱을 다른 화면으로 전환하면 재생을 중단합니다. 실제 주행 안내 중에는 테스트 버튼을 비활성화합니다. 휴대폰 미디어 음량이 0이면 테스트 소리도 들리지 않습니다.

0.4.3 음성 중단 처리: Android TTS의 중단 콜백에서도 음성 재생 상태를 해제합니다. 중단 후 다음 과속 음성과 반복 경고음을 재생할 수 있는지, 이전 음성의 늦은 콜백이 새 음성을 방해하지 않는지 회귀 테스트를 추가했습니다. 이 수정만으로 과거 주행 중 경고가 없었던 원인을 확정할 수는 없습니다.

0.4.2 다중 차량 자동 연결: 키 등록·인증을 완료한 등록 차량 전체를 검색하고 먼저 감지된 연결 가능한 근접 차량에 연결합니다. 수동 선택과 무관하며 연결되는 차량을 화면에서 자동 선택합니다. 한 차량의 연결·인증 또는 기존 연결 중에는 다른 차량으로 전환하지 않습니다. 차량별 재시도를 분리했고 미등록·미인증 차량은 연결하지 않습니다.

0.4.1 안내 설정:
- 화면 상단 **안내 설정**에서 안내 음량 0~100%, 고속도로 100~2,000 m, 일반도로 100~1,000 m를 조절합니다. 거리는 100 m 간격입니다. 슬라이더 조작 완료 시 자동 저장되며 기본값 복원도 지원합니다.
- 기본값은 음량 100%, 고속도로 500 m, 일반도로 300 m입니다. 음량은 휴대폰 미디어 음량에 대한 앱 출력 비율이며 TTS와 띵똥 경고음에 함께 적용됩니다. 0.4.0의 미디어 볼륨 자동 30% 증폭·복원 방식은 제거했습니다. 미디어 음량이 0이면 앱 음량이 100%여도 들리지 않습니다. 새 음량은 다음 음성부터 적용되고, 재생 중 경고음은 즉시 반영됩니다. 0%는 현재 출력도 중지합니다.
- 설정한 거리는 카메라 존재 안내와 과속 경고의 접근 구간에 함께 적용됩니다. 도로 종류 미확인 시 고속도로 설정값을 사용합니다. 주행 중 변경해도 경로를 재탐색하지 않고 다음 위치 갱신에서 반영하며 이미 알린 카메라는 중복 안내하지 않습니다. SDK가 카메라를 늦게 제공하면 설정 거리보다 늦게 안내될 수 있습니다.

0.4.0 변경:
- 고속도로 500 m·일반도로 300 m 알림구간 내 제한속도 +5 km/h부터 “제한속도 XX킬로미터 초과입니다”를 한 번 말하고, 과속 상태가 해제될 때까지 2초 간격으로 2음 경고음을 냅니다. 감속·구간 이탈·GPS 만료·음소거·주차·연결 종료 시 경고음을 멈춥니다.
- 거리 음성은 100 m 단위 반올림(423 → 400, 450 → 500). 50 m 미만은 “잠시 후”. 실제 표시 거리와 판정 기준은 유지합니다.
- 주행 시작 시 “주행시작”을 한 번 안내합니다. 목적지 변경·일시 재연결에서는 반복하지 않고 P단에서 다음 주행을 준비합니다.
- 안내 중 미디어 볼륨을 현재 값의 1.3배로 높입니다(단계 올림, 시스템 최댓값 제한). 출력 종료 시 복원하되 사용자가 중간에 변경한 값은 유지합니다. 미디어 무음 0은 유지합니다.

- 2026-10-23 사용자 휴대폰 로그에서 단발 8초 응답 누락마다 BLE 전체 연결을 다시 만드는 것을 확인했습니다. 같은 BLE 연결에서 3회 연속 누락 전까지 재조회합니다. 단절·기타 오류 및 연속 누락 시에는 기존 재연결을 사용합니다. 전송 시작 실패에는 Android 반환 코드를 기록합니다. 실제 응답 누락 원인 및 실주행 개선 효과는 추가 검증이 필요합니다.

0.3.4에서는 연결 단계·오류와 앱 버전을 날짜·시간·시간대와 함께 앱 내부에 저장합니다. 최근 160개 기록은 다음 연결, 앱 종료·재실행 후에도 유지됩니다. 저장 위치는 앱 전용 `shared_prefs/connection-history.xml`이며, 앱에서 **연결 기록 보기 → 연결 기록 복사**로 확인할 수 있습니다. 기존 0.3.3의 소실된 Logcat 기록은 복구할 수 없습니다. 2026-10-22 연결된 휴대폰에서 프로세스 종료·재실행 후 기존 기록 유지와 새 기록 추가를 확인했습니다. 차량 연결 실패 원인 자체는 아직 미확정입니다.

0.3.3에서는 BLE 신호를 일부 제외할 수 있는 `neverForLocation` 선언을 제거하고 정확한 위치 권한·위치 기능을 검색 전에 확인합니다. VIN 이름 필터로 10초 검색 후 미발견 시 20초 보조 검색으로 전환합니다. 보조 검색 시 휴대폰 화면을 켜 두어야 하며, 여전히 VIN에서 계산한 이름과 정확히 일치하는 연결 가능 신호에만 연결합니다. 실패 시 신호 미수신·일반 신호만 수신·다른 Tesla 형식 신호 수신·대상 차량 연결 불가를 구분합니다. 자동 접근 대기는 기존 저전력 필터 검색을 유지합니다. 실차 검색 실패 원인은 재현 로그 확인 전까지 미확정입니다.

0.3.2에서는 키 등록 중 수신하는 VCSEC 거절 응답의 사유·코드를 표시하며, BLE 검색·연결·서비스 검색·전송 설정의 시간 초과를 구분합니다. 등록 성공은 기존과 같이 서명이 검증된 차량 인증으로만 판정합니다. 차량 등록 실패 시 **연결 기록 보기 → 연결 기록 복사**로 앱 버전, 기기 정보, 단계와 오류를 복사할 수 있습니다. 복사 항목에는 VIN·앱 개인키를 포함하지 않습니다. 이 변경은 진단 보완이며, 보고된 실차 등록 실패 원인은 오류 기록 확보 전까지 미확정입니다.

## 설치와 사용

1. `app/build/outputs/apk/debug/app-debug.apk`를 휴대폰에 설치합니다. Android 8.0 이상 및 Bluetooth LE가 필요합니다.
2. 앱의 **차량 등록**에서 Model 3 / Model Y를 선택하고 VIN 17자리를 입력합니다.
3. 차량 가까이에서 화면을 켜고 **처음 연결하나요? 앱 키 등록**을 누릅니다.
4. 차량의 센터 콘솔 카드 리더에 키 카드를 대고 차량 화면의 등록 안내에 따라 승인합니다. 최대 90초 동안 앱에서 등록 상태를 확인합니다.
5. 등록 후 차량 인증이 성공하면 목적지를 표시합니다. 이후에는 **차량 연결**을 누릅니다.
6. 차량 내비게이션에서 목적지를 설정·변경·취소하면서 앱 화면에 반영되는지 확인합니다. 정상 연결 중 5초마다 조회하며 응답 지연으로 더 늦어질 수 있습니다.
7. **연결 종료** 또는 알림의 종료 버튼으로 세션을 끝냅니다. 연결 중에는 다른 차량으로 전환할 수 없습니다.

제공된 APK는 카카오 키 입력 없이 차량 연결을 시작할 수 있습니다. 정확한 위치 권한을 허용하고, 카카오 개발 앱에 패키지명·키 해시가 등록되어 있는지 확인합니다. 앱 내 카카오 연결 설정은 제거했으며, 업데이트 시 이전 키 입력·비활성화 선택도 정리하고 기본 키를 사용합니다. 자세한 절차는 [KAKAO_SETUP.md](KAKAO_SETUP.md)에 있습니다.

자동 사용은 차량 키 등록·인증을 한 번 마친 뒤 **차량 접근 시 자동 연결**을 켭니다. 근처 기기·정확한 위치·알림 및 위치 **항상 허용** 권한이 필요합니다. 인증을 마친 등록 차량 중 먼저 감지된 차량에 연결해 대기하고, 차량 속도가 3 km/h 이상이면 안내를 시작합니다. 신호 대기에서는 유지하고 P단에서는 중지합니다. 자동 연결 대기에는 지속 알림이 표시되며, 수동 연결에서도 같은 주행 시작 조건을 사용합니다. 자세한 자동 연결 동작은 [AUTO_CONNECT.md](AUTO_CONNECT.md)에 있습니다.

USB 연결 시 설치:

```powershell
adb install -r app/build/outputs/apk/debug/app-debug.apk
```

앱은 차량 정보를 조회하는 `ROLE_VEHICLE_MONITOR` 키를 요청합니다. 키 등록 요청을 보낸 사실만으로 등록 성공을 표시하지 않으며, 차량 인포테인먼트와 인증을 마쳐야 등록을 확인합니다.

## 구현 내용

- Model 3 / Model Y별 VIN 등록·선택과 설정 저장.
- 인증에 성공한 선택 차량의 BLE 접근 감지, 저전력 스캔 대기 서비스와 부팅·업데이트 후 복원.
- 차량 속도 3 km/h 이상에서 안내 시작, 신호 대기 유지, P단에서는 안내만 중지하고 차량 연결은 유지하여 장시간 대기 후 재출발을 감지.
- VIN으로 계산한 Tesla BLE 광고명 검색, GATT 서비스 연결 및 indication/notification 구독.
- MTU 기반 메시지 분할·재조립과 전송 직렬화.
- P-256 ECDH, Tesla KDF, 세션 HMAC 검증, AES-GCM 요청/응답 인증.
- 요청 UUID·발신 도메인·수신 주소로 응답을 구분하고 이전 요청 응답을 무시.
- 목적지 이름·좌표, 남은 시간과 거리 조회. 목적지 취소 시 이전 정보를 제거.
- 카카오내비 SDK를 실제 의존성으로 포함하고 목적지 좌표로 카카오 경로를 탐색.
- 목적지 미설정·취소·경로 탐색 실패 시 안전운행 모드로 전환.
- 도로 매칭 안내 목록에서 과속 관련 카메라만 표시하고 한국어 TTS로 거리·제한속도 사전 안내.
- SDK 도로 종류에 따라 기본 고속도로 500 m·일반도로 300 m 안내(설정 가능). 카메라 접근 구간에서 단속지점 제한속도 +5 km/h부터 과속 음성을 한 번 안내하고, 과속이 지속되면 2초 간격으로 경고음을 반복합니다.
- 위치 만료·경로 이탈·목적지 변경 시 카메라 표시와 음성 초기화, 이전 비동기 응답 무시.
- 화면이 꺼져도 연결을 유지하는 `connectedDevice` 포그라운드 서비스. 카카오 안내 사용 시 `location` 유형을 함께 사용.
- 사용자가 시작한 연결 세션 동안 제한 시간으로 갱신하는 CPU wake lock. 세션 종료 시 해제.
- 연결이 끊기면 차량의 오래된 주행 정보는 비우고 재연결 시 새 인증 세션을 구성합니다. 주행 중 목적지 좌표를 확보했다면 카카오 안내는 유지하며, 기본 재연결 시도를 소진한 뒤에도 안내가 유지되는 동안 30초 간격으로 차량 연결을 다시 시도합니다. 10분간 이동이 확인되지 않으면 안내를 종료합니다.
- 차량별 키 쌍을 Android Keystore의 AES-GCM 키로 암호화해 앱 전용 no-backup 저장소에 보관. Android 8 호환을 위해 ECDH 시 키를 앱 메모리에서 사용.
- 통계 탭(설정에서 켬): 차량별 충전 기록과 주행 기록. 충전은 직전 충전 대비 전비·km당 충전비·전체 평균과 충전별 단가, 주행은 P단 기준 자동 구간 분리와 거리·시간·평균 속도·배터리 변화. 배터리 표시와 같은 충전 상태 조회로 케이블 분리 후 새 충전을 자동 기록하고, 같은 충전을 연결할 때마다 다시 기록하지 않음.
- 앱 자체 로그에 개인키·카카오 앱 키·차량 응답 본문·이동 경로를 기록하지 않음. UI 연결 기록은 메모리에서만 유지. SDK는 지도·경로 처리에 필요한 데이터를 자체 관리.

## 빌드

JDK 17과 Android SDK Platform 34 / Build Tools 34.0.0을 사용합니다. Android Studio에서 프로젝트를 열면 SDK 경로를 설정할 수 있습니다. 또는 무시되는 `local.properties`에 로컬 경로를 지정합니다.

```properties
sdk.dir=C:/Users/YOUR_NAME/AppData/Local/Android/Sdk
kakao.nativeAppKey=YOUR_NATIVE_APP_KEY
```

```powershell
.\gradlew.bat :app:assembleDebug
.\gradlew.bat :protocol:test :app:testDebugUnitTest :app:lintDebug
```

빌드 버전은 Gradle 8.7, Android Gradle Plugin 8.5.0, Kotlin 1.9.24로 고정했습니다. 개인용 진단 APK의 targetSdk는 34입니다. Google Play 배포용 설정은 포함하지 않았습니다.

## 검증 범위

안내 종료 후에도 고정밀 GPS 요청이 남던 문제를 보완했습니다. 안내가 없는 상태가 30초 유지되면 공식 `KNSDKRelease()`로 SDK·위치 수집을 해제하고 다음 주행 때 재초기화합니다. 짧은 주차·목적지 변경·BLE 단절 후 계속되는 안내에서는 해제를 취소해 사용 중인 안내를 유지합니다.

2026-10-30 기준 0.5.19 JVM 테스트 295개와 실제 휴대폰 SDK 해제·재초기화 테스트 1개가 통과했습니다. 안내 대기 중 활성 GPS 요청 0개를 확인했습니다. 주행 중 배터리·통신량 절감률과 차량 재연결은 별도 실주행 확인이 필요합니다.

0.5.19에서는 주행 중 차량 조회는 5초로 유지하고, 확인된 P 주차에서는 차량 상태 15초·차량 위치 60초로 줄였습니다. 신호 대기나 기어 미확인은 주차로 취급하지 않으며, 주차 중 출발 감지는 다음 조회까지 최대 약 15초와 응답 시간이 걸릴 수 있습니다. 화면의 차량 조회 주기와 인터넷 경로 탐색을 구분해 표시합니다. 목적지가 같으면 기존 경로를 유지하고, 이름 변경·20 m 이내 좌표 변화로는 재탐색하지 않습니다. 목적지 취소·실질적인 변경·SDK 경로 이탈 처리는 유지합니다.

연결 중에는 추가 차량 접근 검색을 중지하고 연결 세션이 끝나면 다시 검색합니다. Bluetooth 연결 이벤트는 즉시 반영하되 누락 이벤트를 보정하는 점검은 10초에서 30초로 줄였습니다. 주차·차량 대기 중 내부 점검은 5초, 안내 중에는 1초입니다. 카카오 경로의 동일 GPS 좌표를 반복 투영하는 계산을 줄였습니다. 안내 중 5분마다, 안내 종료 시 연결 기록에 앱 경로 탐색 수·SDK 경로 확인 수와 앱 전체 UID 네트워크 수신/송신 증가량을 남깁니다. 이 통신량은 카카오 요청별 사용량이나 과금되는 모바일 데이터만을 뜻하지 않으며, 배터리 절감률은 실주행 전후 비교가 필요합니다.

0.5.18에서는 주행 정보와 차량 위치를 별도로 조회해 BLE 응답 크기 초과(코드 25)로 위치 조회가 중단되는 문제를 수정했습니다. 위치 조회의 일시 오류·응답 누락은 다음 주기에 재시도하며 이미 받은 주행 정보는 유지합니다.

휴대폰 GPS가 10초 이상 갱신되지 않으면, 미리 확인한 카카오 목적지 경로와 최신 차량 좌표로 경로상의 카메라까지 남은 거리를 계산합니다. 화면에 `차량 위치로 보조 안내 중`을 표시하고, GPS가 복구되면 기존 안내로 돌아옵니다. 차량의 추정 좌표가 계속 갱신되면 원시 GPS 시각이 멈춘 터널에서도 사용할 수 있습니다. 차량 좌표도 멈추거나 오래됐을 때, 경로 이탈·방향 불일치·모호한 도로 매칭은 안내를 보류합니다. 목적지 경로 없이 시작한 안전운행 모드는 차량 위치 보조를 사용하지 않습니다. 차량의 좌표 제공 여부와 터널 내 추정 위치 갱신은 실차 확인이 필요합니다.

`protocol` 테스트는 Tesla 공식 문서의 고정 암호화 예제와 ECDH의 0 패딩 벡터, BLE 분할·만료, 키 등록 권한, 암호화된 목적지 조회·변경·취소, 서명/암호문 변조 및 이전 응답 혼입을 검증합니다. 충전 상태는 정격 주행 가능 거리의 km 변환, 필드 누락·비정상 값, 응답에 충전 정보가 없는 경우와 차량 거절 사유를 구분하는지, 충전 상태 조회의 세션 오류가 세션 재설정을 일으키지 않는지 확인합니다. 주행 상태 조회는 차량 오류 응답에 주행 상태가 붙어 있어도 거절 사유로 실패하는지 확인합니다.

앱 JVM 테스트는 Robolectric에서 첫 화면, 차량 등록, 잘못된 VIN 처리와 차량 선택 저장을 확인합니다. 이는 실제 Android Bluetooth 스택이나 Keystore 하드웨어 테스트를 대체하지 않습니다.

개인 휴대폰에서 Gradle `connectedDebugAndroidTest`를 사용하지 않습니다. AGP/UTP가 종료 시 대상 앱까지 제거해 차량 키·설정·기록을 지울 수 있어 기본 차단했습니다. 해당 작업은 데이터가 없는 전용 테스트 기기에서만 `-Ptesla.disposableTestDevice=true`로 실행합니다. 개인 기기의 SDK 정리 검증은 `assembleDebugAndroidTest`로 테스트 APK만 만들고, 두 APK를 `adb install -r`로 설치한 뒤 `adb shell am instrument -w -e class dev.teslanavi.navigation.KakaoIdleReleaseDeviceTest dev.teslanavi.test/androidx.test.runner.AndroidJUnitRunner`로 직접 실행합니다. 종료 후 제거할 대상은 테스트 패키지 `dev.teslanavi.test`뿐이며 본 앱을 제거하거나 데이터를 초기화하지 않습니다.

카메라 테스트는 목적지 변경·취소, 차량 전환, 이전 경로 응답, 동일 경로의 반복 탐색 방지, GPS 만료, 안내 중복 억제, 음소거, 음성 엔진/오디오 포커스 오류와 SDK 카메라 분류를 확인합니다. 기본 키가 포함되어 있다는 사실은 SDK 서버 인증 성공으로 표시하지 않습니다.

키 기본값은 Git에서 제외된 `local.properties`의 `kakao.nativeAppKey`를 빌드 시 읽어 APK에 포함합니다. 해당 값을 생략한 빌드는 카메라 안내가 비활성화됩니다. 키 변경은 개발 컴퓨터에서 수정 후 다시 빌드합니다. 현재 SDK 연동에는 REST API 키를 사용하지 않습니다.

실차에서 확인할 항목:

- Model 3와 Model Y 각각의 차량 소프트웨어 버전과 조회 권한 지원.
- 실제 키 카드 등록과 인포테인먼트 동기화, 목적지 필드의 제공 여부.
- 화면 잠금 상태 장시간 연결, Bluetooth 재접속 및 휴대폰 절전 정책.
- 충전 상태 조회 권한(`ROLE_VEHICLE_MONITOR`), 주행거리·충전량 필드 제공 여부와 충전·주행 자동 기록. 충전량이 같은 충전을 잡으려고 배터리 3%p 이상 상승도 새 충전으로 보는데, 충전 조회가 실패한 사이 긴 내리막 회생제동으로 배터리가 오르면 이전 충전이 한 번 더 기록될 수 있습니다. 이때는 해당 기록을 삭제합니다.
- 본인 카카오 앱 키의 SDK 인증, 실제 GPS·카메라 데이터 수신, 카카오/테슬라 경로 차이와 TTS 음성 출력.

키 등록 후 조회 권한 오류가 나면 연결 기록의 코드와 차량 소프트웨어 버전을 확인합니다. 앱 데이터 삭제·재설치는 새 키를 만들기 때문에 차량에서 이전 앱 키를 정리하고 다시 등록해야 합니다.
